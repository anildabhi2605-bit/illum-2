# P05-T05 — Validate provider responses and classify retries

**Phase:** P05 — Provider interface and first tested adapter  
**Initial status:** NOT STARTED / NOT VERIFIED  
**Task dependency:** P05-T01–T04.

## 1. Goal
Prevent malformed results and unsafe retry loops.

## 2. Source inputs
Schema validation library and normalized error taxonomy.

Use the original requirements as described in `../../01_BASELINE/PRODUCT_RULES_AND_INVARIANTS.md`; read the related feature spec and the source-of-truth files referenced in `../../00_START_HERE/README_START_HERE.md`. If the source does not define a detail, record it as open; do not silently make it part of the approved product behavior.

## 3. Build steps
1. Validate response schema for structured requests.
2. Define bounded retry policy for transient errors only.
3. Exclude invalid key/access/region/billing/model-not-found from blind retries.
4. Respect provider retry guidance.
5. Handle timeout where request may have completed.

## 4. Expected deliverables
Response validation and retry policy service.

## 5. Acceptance criteria
Schema-invalid output is not saved; retry count bounded; non-transient errors stop.

## 6. Required tests
Failure injection for every error category, schema invalid, timeout.

Run automated tests first, then required integration/manual tests. Record exact command, environment, result and evidence. Tests that were not executed must be labelled NOT RUN; do not infer pass from implementation appearance.
