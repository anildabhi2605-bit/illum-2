# P02-T02 — Harden repository ignore rules and example config

**Phase:** P02 — Configuration and secret safety  
**Initial status:** VERIFIED (2026-10-31)  
**Task dependency:** P01-T01; P02-T01.

## 1. Goal
Prevent accidental commits of local secrets/data.

## 2. Source inputs
Repo layout and secret policy.

Use the original requirements as described in `../../01_BASELINE/PRODUCT_RULES_AND_INVARIANTS.md`; read the related feature spec and the source-of-truth files referenced in `../../00_START_HERE/README_START_HERE.md`. If the source does not define a detail, record it as open; do not silently make it part of the approved product behavior.

## 3. Build steps
1. Add `.env.example` placeholders only.
2. Add `.gitignore` for `.env`, venv, DB/data, cache, exports, logs and temp files as appropriate.
3. Verify any currently tracked secret/data is removed from tracking safely if present.
4. Add a repository check for accidental secret files.

## 4. Expected deliverables
`.env.example`, `.gitignore`, secret hygiene check.

## 5. Acceptance criteria
`.env` and local data do not appear in tracked files; example contains no real token.

## 6. Required tests
Check `git check-ignore`, tracked-file enumeration and sentinel scanning.

Run automated tests first, then required integration/manual tests. Record exact command, environment, result and evidence. Tests that were not executed must be labelled NOT RUN; do not infer pass from implementation appearance.

## 7. Out of scope / prohibited shortcuts
Do not commit a real provider key, even for tests.

- Do not start the next task automatically.
- Do not change protected skill prompts/contracts without recorded user approval.
- Do not claim a connector/provider is supported without adapter and test evidence.
- Do not log or export secrets.

## 8. Blocker conditions
If a secret has already been committed, treat as compromised and recommend provider-side revocation; cleaning Git alone is not enough.
