# P02-T01 — Implement typed configuration loading

**Phase:** P02 — Configuration and secret safety  
**Initial status:** NOT STARTED / NOT VERIFIED  
**Task dependency:** P01 complete; P00 decisions.

## 1. Goal
Load `.env` and validated application settings safely at startup.

## 2. Source inputs
Config spec; provider names that have been approved for implementation.

Use the original requirements as described in `../../01_BASELINE/PRODUCT_RULES_AND_INVARIANTS.md`; read the related feature spec and the source-of-truth files referenced in `../../00_START_HERE/README_START_HERE.md`. If the source does not define a detail, record it as open; do not silently make it part of the approved product behavior.

## 3. Build steps
1. Define config schema and defaults.
2. Load local `.env` at startup without requiring every provider key.
3. Validate malformed values and allowed enums.
4. Separate non-secret settings from secret values.
5. Avoid exposing raw environment object to UI.

## 4. Expected deliverables
Configuration module and startup validation.

## 5. Acceptance criteria
Missing optional key does not crash app; invalid required config gives sanitized actionable error; secret values are not serialized.

## 6. Required tests
Unit tests for absent, empty, malformed and valid settings; sentinel-secret redaction test.

Run automated tests first, then required integration/manual tests. Record exact command, environment, result and evidence. Tests that were not executed must be labelled NOT RUN; do not infer pass from implementation appearance.

## 7. Out of scope / prohibited shortcuts
Do not assume every candidate provider exists.

- Do not start the next task automatically.
- Do not change protected skill prompts/contracts without recorded user approval.
- Do not claim a connector/provider is supported without adapter and test evidence.
- Do not log or export secrets.

## 8. Blocker conditions
A provider key variable is added only with a deliberate adapter/config decision.
